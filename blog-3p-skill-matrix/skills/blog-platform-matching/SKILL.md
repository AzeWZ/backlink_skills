# 博客：平台匹配调研

先阅读[术语约定](../../docs/terminology.zh-CN.md)。这是写前只读匹配服务；另有独立授权的账号准备服务，不能由本角色代做。当前 schema 2.14 的每篇文章都必须在 WQ/WR 派发前取得用户确认的人工发布平台/账号映射；本技能只研究用户已提供的 XLSX、表格或消息中出现的平台/账号候选，输出建议和不确定性；不创建文章交付目录、不写文章，不启动 WQ/WR，不注册/登录，不处理验证码，也不操作编辑器。

本技能对应[流程核心](../../docs/workflow-core.md)的写前只读调研，完成匹配建议后回到 G 的一次完整方案确认，不另设平台审批回合。复用同一可见调研角色和适用来源，仅补足影响匹配决定的证据；不为了填满候选数量、收集热门模板或消除所有未知反复检索。证据不足时保留不确定性并给出待用户决定项，不自行扩展候选或将“尚不确定”写成“已适配”。

## 输入与边界

- 读取用户原始候选资料及其哈希、精确行/单元格/消息定位，文章语言、市场、内容类型和人工发布要求。区分用户要求的品牌展示方式与关系披露：`founder` 只说明作者关系，不证明平台允许品牌账号或文章页已展示品牌；用户未要求机构身份时，不自行排除真实创始人署名。
- 公开平台页面、政策、格式说明、语言支持、公开样本和历史证据只能说明可承接性；它们不能自行创建候选、账号映射或允许范围。
- 每个建议都必须保持“该文章 + 该平台 + 该账号”的一对一关系；不复用平台名或平台/账号组合，也不把已验证账号当成通用平台池。
- 对每篇候选明确分开两层证据：`primary_reader_languages` / `primary_reader_markets` 与其公开受众证据，和 `transport_supported_content_languages` 与其编辑器或格式传递证据。能显示、保存或阅读英语只属于后者，不能证明英语或全球英语是该平台的主读者受众。
- 已观察到的发布问题只能作为同一平台、同一账号、同类交接的传输风险问题，必须记录观察日期与读者页/编辑器面；它们不能替代读者语言、市场、需求、审核原因或账号授权证据。无同账号观察时，保持 `UNVERIFIED`，不要把其他账号或旧文章的结果外推为平台能力。
- 若文章语言或市场不匹配候选平台的主读者，提案只能标成需逐篇确认的 `CROSS_LANGUAGE_EXCEPTION_OWNER_CONFIRMED`，不能把它写成普通 `COMPATIBLE`。匹配子角色不能自行批准例外。
- 无法证明时写 `UNVERIFIED` 和风险，不臆造“热门”“支持”或登录/发布能力。任何付费、账号、政策、语言或格式疑点都清楚标出给用户决定。

## 判断是否值得发布

先排除明确冲突，再比较合适候选，不使用固定分数、域名形式或“能建博客”直接排序。四类判断复用现有报告及来源：

| 判断 | 需要回答的问题 |
| --- | --- |
| 读者与政策 | 主读者语言、市场、主题是否适合本篇？规则是否允许本次内容、必保留 CTA 及披露？ |
| 品牌展示 | 文章页实际显示品牌频道、机构作者、创始人关系还是仅个人署名？是否满足本次用户要求？ |
| 文章入口与链接 | 是否有独立公开网址、栏目/标签/作者页等实际入口？正文链接是否可点击，是否带 `nofollow`、`ugc` 等属性？ |
| 人工成本与风险 | 能直接发文还是须先建博客、补资料？已知付费、审核、图片或格式限制有哪些？哪些仍未核验？ |

- 语言/市场/主题明显不匹配、政策与必保留 CTA 冲突，或无法满足明确品牌要求时，不作普通推荐；按原规则说明缺口、排除理由或待用户决定项。不能为凑数量降低要求，也不能为适应平台删除 CTA。创建品牌频道/博客属于人工发布准备，不授权本角色操作。
- 新用户是否注册/验证后直接发文，或须另建博客/频道，要单独说明。使用现成资料与默认布局即可完成的简单设置有价值，不按“要建博客”一律排除；需要装修、域名/DNS/代码、付费或持续试错的额外建设默认不采用，交用户决定。没有可靠依据时写未知，后续由获授权的[账号准备服务](../../docs/account-preparation.md)有限核查，不为查清设置全面调查后台。弱分发入口、`nofollow`/`ugc` 或未知功能不自动否决；核心受众证据及跨语言确认要求不变。
- 推荐顺序综合考虑：读者与政策适配 → 本次品牌要求 → 实际文章入口 → 发布维护成本 → 长期经营价值。这是判断顺序，不是打分公式。身份与分发兼顾、简单设置即可发文的品牌博客/频道可以推荐，不要求先有长期经营计划；专门建设和持续维护则需用户明确计划。不强制三至五篇或装修，也不让“账号已经注册”压过受众适配与新增成本。
- 子目录/子域名、平台知名度、链接属性和同平台其他页面已收录，都不能证明本篇会收录、传递排名价值或带来访问。自控账号在第三方域名发文不是独立第三方背书。建议说明可观察优势与代价，不承诺“收录快”“权重高”或“外链有效”。
- 只补查会改变建议的缺项，优先研究最适合的来源内候选；证据足够就停止，不逐站全面调查。复用有日期、范围适合的公开规则，账号状态仍分别核对，不推断登录成功。未能匹配的文章只报缺口，不自行换平台、缩减数量或启动监测。

## 输出

写入 `evidence/platform-matching/platform-matching-report.md` 和 `platform-matching-proposal.json`。对每篇文章说明：用户来源定位、候选平台/账号、文章语言/市场、主读者语言/市场及其证据、可观察到的传递语言支持及其证据、`fit_mode`、格式/人工传递适配、证据 URL/日期、限制、不确定性和建议。提案必须可追溯，却不能声明已冻结或已获授权。平台样本/画像最多帮助决定技术深度、语气、示例类型和交付形式；不能作为主关键词、自然变体、搜索意图、当地需求、热门度或选题成立的证据。

使用[简短报告模板](../../templates/platform-matching-report.md)。`rationale` 写一段推荐理由与主要代价，不复述全部证据；读者适配沿用 `audience_compatibility`。其余观察可放在提案的可选 `selection_notes`，引用已有证据路径/片段，不另写逐项报告或重复来源包。旧提案无此字段仍可读取，不补历史、不新增机器硬门。无必要备选时不凑备选；存在备选时仅放在报告比较，正式 `proposals` 仍按现有逐篇唯一映射填写。

G 检查来源、一对一结构及建议是否覆盖用户的品牌展示、CTA、数量和人工交付要求，再汇入原写前方案；不另行排序或替用户选。只有用户把每一个 `{platform, account}` 明确确认到 `owner-platform-selection.json`，让 `platform_scope.allowed_pairs` 成为其机械投影，并为每篇填入兼容的语言－平台记录后，文章协作组才可启动。缺候选、无可靠建议或用户未确认时，结果为 `OWNER_DECISION_REQUIRED`；不得替用户选、换、补或扩展平台范围。历史 schema 2.8 可供读取或校验，但不能绕过当前人工发布映射要求。

按需读取[平台选择契约](../../docs/owner-platform-selection.md)的来源与确认条款；只有匹配平台存在实质读者传递风险时，才读取[平台样本画像](../../docs/platform-style-profiles.md)的相关段落。机器字段、JSON 键、状态码和路径保持不变。
