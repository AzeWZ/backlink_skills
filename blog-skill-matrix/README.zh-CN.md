# 规模化 SEO 博客写作工作流

[English](README.md) · 版本 0.14.0 · [MIT 许可证](LICENSE)

**从读者问题出发，交付有用的文章、贴题的图片和可直接复制的发布页。**

Scalable SEO Blog Workflow 是一套面向持续内容制作的开源 AI 技能组合，完成研究、自然本地化、写作、配图、质量审核与人工发布交接。适用于品牌内容、跨语言 SEO 和第三方平台文章，兼顾逐篇质量、用户要求与任务成本。

这里的“规模化”指多篇独立文章可以有序推进：复用仍适用的资料与工作角色，按篇完成检查和交付。一篇受阻不必拖住其他已确认任务；它不表示套模板大量生成、无限并发或自动发布。单篇任务同样适用。

## 为什么使用这套工作流

- **围绕具体问题写文章。** 从“谁需要解决什么问题”确定选题，正文提供可用的解释、步骤或选择依据，产品推荐与当前任务衔接。
- **跨语言 SEO 有依据。** 保留用户关键词的核心含义，优先采用适用的品牌本地表达，再查目标地区自然变体；标题突出各篇问题，不重复套用同一长前缀。
- **品牌与平台一起适配。** 图文尽量呼应品牌风格，平台匹配依据实际文章的主流语言和内容类型，并始终限制在用户给定范围。
- **图片参与解释。** 正文图对应相邻方法和准确位置，封面单独准备；实际查看每张最终图片，不只检查文件是否存在。
- **审核最终成品。** 可选独立 R 审可视化载荷、实际图片与重要来源；只修真实问题，不把一次局部修复变成反复全文审稿。
- **交付方便人工使用。** 同源 HTML/Markdown、中文插图提示、可见 Alt、SEO 字段和 Excerpt 一起准备，发布者可以按统一顺序取用。
- **减少流程额外开销。** 共享资料复用、少量代理持续工作、程序整理与计数，让更多工作量用于文章本身，而不是重复交接。

## 最终交付什么

文章可在浏览器中查看、选中并复制到富文本编辑器，不是让发布者面对 HTML 源码。

| 交付内容 | 用途 |
| --- | --- |
| 可视化 HTML 发布页 | 分开复制标题和正文；准确位置显示中文插图提示与本地化 Alt |
| 同源 Markdown 备用页 | 适用于 Markdown 编辑器，或作为可读备用稿 |
| 编号 PNG/JPG/JPEG 正文图 | 与相邻段落对应，按确认数量与首中尾需要组织 |
| 额外独立封面 | 对应文章主题与品牌风格，不占正文图数量 |
| SEO title、tags、description | 在页面底部分字段取用 |
| Excerpt（文章摘要） | 与 SEO description 分开，供平台摘要栏或文章卡片使用 |

发布页没有复制按钮。它保持统一简单的布局：**标题 → 正文与图片注释 → SEO 信息 → Excerpt**。

一份稿件和一组素材支撑全部交付，不要求模型重复填写多份正文、元数据和图片清单。来源说明留在稿件信息中；正常通过只留简短质量结论，有问题才记录。

## 工作流程

```text
G：调研与写作方案
        ↓
用户确认完整范围
        ↓
W：成稿、配图、封面，生成并检查 HTML / Markdown 载荷
        ↓
按已确认的质量路线，二选一：
  ├─ 默认作者自查：W 在同一上下文完整自查
  └─ 独立审稿：R 审最终载荷、实际图片与重要来源
        ↓ 质量通过
G：对照原要求验收，正式交用户
        ↓
人工发布，回传 URL 与接受／需修复结论
        ↓ 人工接受后
同一 G：公开页只读检查
        ↓ 检查通过
完成：人工接受 + 公开页检查通过

平台侧问题 → 人工修复 → 重新接受后，同一 G 仅复核相关项
```

两条质量路线选其一；选择 R 时不再叠加 W 的正式完整自查。平台侧修复不重开写作审稿。

| 角色 | 负责什么 |
| --- | --- |
| G：`blog-gate` | 统筹调研、确认要求、安排作者、验收需求、检查公开页 |
| W：`blog-writer` | 连续研究、关键词本地化、写作、配图、制作载荷 |
| R：`blog-review`（可选） | 用户明确选择后，独立检查最终可视化载荷、图片、封面与重要来源 |

R 收到的是已经生成并机械检查的最终 HTML/Markdown 载荷，不是等待排版的源稿。它检查文章是否有用、事实、SEO 与语言、图文准确性、推荐与链接，以及载荷可用性。通过后才交 G 验收并正式给用户发布。

### 发现真实问题时

```text
真实问题
   → 原 W 定向修复、重生成载荷
   → 原 W 或 R 只复核变更及直接影响
   → 问题关闭后，回到 G 验收
```

无法关闭的重大问题或范围变更交用户决定，不能带着问题交付。内容修改回原作者，平台侧传输修复由人工完成；旧结论不自动覆盖新版本。

## 任务成本怎么控制

成本是本工作流的一项设计重点，不是唯一目标。文章数量、研究/本地化难度、所选模型、上下文、修复和图片规格决定实际用量；不承诺固定每篇价格或未经测量的节省比例。

| 路线 | 每篇主要模型工作 | 成本取舍 |
| --- | --- | --- |
| 默认：作者自查 | W 连续制作文章、图片和载荷，在同一上下文自查 | 减少独立交接与重新理解背景 |
| 可选：独立审稿 | W 连续制作；复用的 R 在载荷完成后完整审一次 | 增加独立阅读和看图成本，获得作者之外的检查视角 |

两条路线都共享 G 的统一统筹与需求验收，公开页按实际 URL 回传批次检查。独立 R 替代作者的正式完整自查，不与之叠加；表中安排不代表固定 API 调用次数或 token 账单。

减少开销的方法是：复用适用资料，一份 Markdown 生成双载荷，程序处理计数和一致性，只复核真实改动，不写全绿报告；等待人工消息时停止重复运行。正常稿保持一次完整质量核验，不靠遗漏需求减少工作。

研究、正文、实际看图与必要修复仍需模型用量，图片生成可能单独收费；正文图和额外封面按确认规格准备。工具调用、结果读取和人工发布也有成本，并行主要缩短等待，不保证更省 token。

## 开始使用

在已接入本工作流技能的环境中，从 `$blog-gate` 启动。下面的请求可按实际任务替换：

```text
$blog-gate

品牌与目标页面：<产品页面 URL>
候选平台：<我提供的平台清单或文件>
文章数量：3 篇，每篇一个不同平台
关键词：<必须保留的核心含义与可扩展方向>
CTA：<指定锚文本、链接和创始人关系披露>
图片：<正文图数量、比例与风格要求；另备封面>

先汇报逐篇调研结果、语言/平台匹配和写作方案，等我确认后写作。
采用独立审稿：由复用的 R 审最终载荷与实际图片，
只修真实问题，不常规全文复审。
交付 HTML、Markdown、图片、SEO 信息与 Excerpt，由我人工发布。
```

独立审稿是这个示例的明确选择，不是默认增加的环节。若采用作者自查路线，把相应要求改为“采用作者自查，不启动独立 R”。

当前目录仍为 `blog-skill-matrix`，调用入口仍是 `$blog-gate`；本次更新的是项目展示名，不改变现有使用方式。首次接入时保留整个目录，包括内部工具、模板和参考资料，只注册三个技能入口；不要只复制三个 `SKILL.md`。具体接入方式遵循所用工具的技能安装规则。

## 内容质量与任务边界

- **平台与语言有依据。** 只在用户提供的平台范围内研究和推荐，由用户确认映射。平台主流语言依据实际首页、热门或精选文章，不用界面语言、历史账号或“能显示”代替；不擅自扩展或替换平台。
- **SEO 服务具体读者问题。** 每篇保留用户关键词的全部核心含义，标题突出自己的问题，避免同一长前缀模板；H2/H3 具体，不机械设词频。跨语言优先适用品牌本地表达，再查地区自然变体，仍无共识才记录翻译兜底。可选 Trends 不证明搜索量或当地热度。
- **文章先有独立价值。** 正文有可用的答案和可靠事实；产品推荐次要但指定 CTA、锚文本、链接和关系披露必须保留。多锚多链接按用户约定，不自行设上限，也不承诺排名、收录或零删除风险。
- **图片真正解释内容。** 逐张查看最终图片及封面，检查方法、连续示例和品牌风格；不能靠文件存在或尺寸合规代替。
- **本地交付不等于公开完成。** 工作流不操作文章编辑器、不上传图片、不保存草稿或自动发布。账号准备需[单独授权](docs/account-preparation.md)。人工接受且公开检查通过，才计完成。

## 运行与深入阅读

需要支持本地技能与文件工具的环境，以及 Python 3.9+。Markdown 生成依赖 `markdown-it-py==3.0.0`，建议在隔离环境安装：

```sh
python -m pip install -r skills/blog-human-handoff/scripts/requirements.txt
```

内部目录名称保留以兼容已有代码；它们不是额外的技能入口。已有 `campaign.json`、文章包或审稿索引项目继续原规则，不自动迁移。
