# 规模化 SEO 博客写作工作流

[English](README.md) · 版本 0.15.0 · [MIT 许可证](LICENSE)

**围绕读者问题写文章，配上准确的插图，交付可直接复制的发布页。**

Scalable SEO Blog Workflow 是一套用于搜索引擎优化（SEO）文章制作的开源 AI 技能，涵盖调研、多语言写作、配图、独立审稿和人工发布准备。适合品牌内容、跨语言 SEO 和第三方平台发文。

单篇和多篇任务都能使用。多篇任务可复用调研资料、作者与审稿代理，逐篇完成交付，兼顾质量和成本。

## 为什么使用这套工作流

- **交付稿件兼顾 SEO 与外链质量。** 保留关键词与搜索意图，让正文链接服务读者问题；匹配平台语言与规则，减少可避免的删帖风险，避免外链农场式内容。
- **围绕具体问题写文章。** 先确定读者和问题，再给出清楚的解释、可执行的步骤或选择依据，结合文章内容推荐产品。
- **跨语言 SEO 有依据。** 保留关键词的核心含义，优先参考品牌网站已有的当地用语，再查目标地区的常用表达。每篇标题突出自己的读者问题。
- **兼顾品牌风格与平台读者。** 图文尽量与品牌一致，根据平台首页、热门和精选文章判断受众语言与内容偏好。
- **用图片讲清方法。** 插图放在对应段落旁，准确解释操作或概念；逐张查看最终图片，另备独立封面。
- **审核最终成品。** 独立审稿者查看最终发布页、实际图片和重要来源，修复后复核相关改动。
- **交付方便人工使用。** 从一份稿件生成 HTML 和 Markdown 发布页，附中文插图提示、图片替代文本（Alt）、SEO 信息和文章摘要（Excerpt），方便逐项复制。
- **减少流程额外开销。** 复用调研资料与工作代理，由程序生成发布页、核对链接数量和文件一致性。

## 交付稿件的 SEO 价值

- **标题与正文围绕同一搜索目标。** 标题保留用户要求的关键词含义，正文回答相关的具体问题；不同文章围绕主关键词提供不同答案。
- **链接有内容支撑。** 正文提供独立有用的内容，产品推荐说明它能帮助读者完成哪一步，保留指定的行动引导链接（CTA），并说明作者与产品的关系。
- **减少可避免的删帖风险。** 根据平台文章选择语言与写法，核对规则，说明作者与产品的关系，重要事实有来源支持。
- **避免为挂链接而写文章。** 每篇内容有用且各有侧重，链接与当前问题相关。用户指定多个锚文本或链接时，按约定保留并核对规则；介绍、推荐和来源中的目标链接统一按出现次数计算。
- **检查从稿件到公开页的内容一致性。** 审稿者检查最终发布页中的标题、SEO 信息、摘要、链接和图片；人工发布后，主控核对公开页是否正确保留这些内容。

内容与链接按 [Google 垃圾内容政策](https://developers.google.com/search/docs/essentials/spam-policies)和平台规则检查，要求有冲突时交用户决定。排名、收录和删帖由搜索引擎或平台决定。

## 最终交付什么

在浏览器中打开发布页，即可选中并复制到富文本编辑器。

| 交付内容 | 用途 |
| --- | --- |
| 可视化 HTML 发布页 | 分开复制标题和正文；在对应段落显示中文插图提示和文章语言的 Alt |
| 内容一致的 Markdown 备用页 | 适用于 Markdown 编辑器，或作为可读备用稿 |
| 编号 PNG/JPG/JPEG 正文图 | 对应相邻段落，数量与开头、中段、结尾的位置按方案准备 |
| 额外独立封面 | 对应文章主题与品牌风格，不占正文图数量 |
| SEO 标题、标签、描述 | 在页面底部分别复制 |
| Excerpt（文章摘要） | 供平台摘要栏或文章卡片使用，与 SEO 描述分开 |

发布页按统一顺序排列：**标题 → 正文与图片注释 → SEO 信息 → 文章摘要**。选中文字即可复制。

一份稿件和一组素材生成全部交付，来源说明随稿保存。

## 工作流程

G 是主控，W 是作者，R 是独立审稿者。

```text
G：汇总调研，提出逐篇写作方案
        ↓
用户确认方案
        ↓
W：写作、配图，生成并检查 HTML / Markdown 发布页
        ↓
R：完整审核最终发布页、图片、封面和重要来源
        ↓ 质量通过
G：对照原要求验收，交付给用户发布
        ↓
人工发布，回传公开网址并说明是否接受发布结果或需要修复
        ↓
原 G：核对公开页与交付稿
        ↓ 用户接受且检查通过
任务完成

平台排版或复制内容有误 → 人工修复 → 原 G 复核相关内容
```

| 角色 | 负责什么 |
| --- | --- |
| G：`blog-gate` | 统筹调研、确认要求、安排作者、验收需求、检查公开页 |
| W：`blog-writer` | 调研、关键词本地化、写作、配图、制作发布页 |
| R：`blog-review` | 审核最终发布页、图片、封面与重要来源 |

### 发现问题后

```text
R 指出问题及位置
   → 原 W 修改并重新生成发布页
   → 原 R 复核修改及相关内容
   → 通过后交 G 验收
```

重大问题无法解决，或需要改变已确认方案时，交用户决定。审核结论对应修改后的版本。

## 任务成本怎么控制

成本主要来自调研、写作、图片、审稿和返修，随文章数量、语言难度、模型及所需上下文而变化。

- 复用有效调研资料和工作代理，减少重复读取背景。
- 一份 Markdown 生成两种发布页，由程序检查计数和一致性。
- R 完整审稿一次，修改后只复核受影响的内容，通过时留简短结论。
- G 验收用户要求，并按回传网址分批检查公开页。
- 等待人工操作时保存进度，收到消息再继续。

图片生成可能单独收费。并行可缩短等待；token（模型处理的文本单位）消耗按实际记录统计。

## 开始使用

在已接入本工作流技能的环境中，从 `$blog-gate` 启动。下面是一个请求示例：

```text
$blog-gate

品牌与目标页面：<产品页面 URL>
候选平台：<我提供的平台清单或文件>
文章数量：3 篇，每篇一个不同平台
关键词：<必须保留的核心含义与可扩展方向>
CTA：<指定锚文本、链接和创始人关系披露>
图片：<正文图数量、比例与风格要求；另备封面>

先汇报每篇的调研结果、语言与平台是否合适，以及写作方案，等我确认后写作。
交付 HTML、Markdown、图片、SEO 信息与 Excerpt，由我人工发布。
```

安装时保留完整 `blog-skill-matrix` 目录，按所用工具的安装规则注册 `blog-gate`、`blog-writer` 和 `blog-review` 三个入口。

## 任务边界

平台由用户提供并确认，语言依据平台实际文章选择。用户确认逐篇方案后开始写作和生成图片。发布由人工完成；机器不得操作文章编辑器、上传文章图片、保存草稿、发布或删除。账号准备需[单独授权](docs/account-preparation.md)。

## 运行与深入阅读

需要支持本地技能与文件工具的环境，以及 Python 3.9+。Markdown 生成依赖 `markdown-it-py==3.0.0`，建议在隔离环境安装：

```sh
python -m pip install -r skills/blog-human-handoff/scripts/requirements.txt
```

内部工具随完整目录一起安装。已有 `campaign.json`、文章包或审稿索引的旧项目，按原规则维护。
